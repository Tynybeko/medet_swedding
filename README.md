# Salome & Nika — свадебный сайт

Приглашение по мотивам occavia.com (шаблон «roses») + фотостена гостей с модерацией.

## Запуск локально

```bash
npm install
npm start            # http://localhost:3000
```

Пароль админа по умолчанию — `admin123`. Свой пароль:

```bash
ADMIN_PASSWORD=мой-секрет npm start
```

Локально фото хранятся в `uploads/`, метаданные — в `data/photos.json`.

## Деплой на Vercel

Приложение работает как одна serverless-функция (`api/index.js` + `vercel.json`),
а фото хранятся в **Vercel Blob** (облачное хранилище, ничего не теряется).

1. В панели Vercel откройте проект → вкладка **Storage** → **Create Database →
   Blob** → подключите к проекту. Vercel сам добавит переменную
   `BLOB_READ_WRITE_TOKEN` — по ней приложение переключается с диска на облако.
2. В **Settings → Environment Variables** добавьте `ADMIN_PASSWORD`
   со своим паролем (иначе останется `admin123`).
3. Запушьте репозиторий — Vercel пересоберёт сайт.

Без Blob-хранилища сайт на Vercel работать не будет (диск там только для
чтения) — шаг 1 обязателен.

На Vercel правка текстов = правка `content.json` в репозитории + push
(файловая система serverless не изменяема).

## Страницы

| Адрес | Что это |
|---|---|
| `/` | Приглашение (GSAP-анимации, отсчёт, RSVP) |
| `/album.html` | **Альбом** — только фото, опубликованные админом |
| `/camera.html` | Съёмка/загрузка фото гостем (сюда ведёт QR) |
| `/qr.html` | Страница с QR-кодом — распечатать и поставить на столы |
| `/admin.html` | Админка: публикация и удаление фото (по паролю) |

## Тексты — content.json

Все тексты сайта лежат в `content.json`. Правите файл → страница подхватывает
изменения сама в течение ~3 секунд, без перезагрузки. Там же дата свадьбы
(`hero.isoDate` — для обратного отсчёта), программа дня и ссылка на карту.

## Как работает фотостена

1. Гость сканирует QR → открывается `/camera.html`, камера запускается сразу.
   Снимок делается через ImageCapture (полное разрешение сенсора), фолбэк —
   canvas JPEG 95% или нативная камера телефона.
2. Лимит — **10 фото на гостя**, и он считается на сервере **по IP-адресу**
   (плюс id браузера): смена браузера, режим инкогнито или очистка localStorage
   лимит не сбрасывают. В новом браузере гость по-прежнему видит свои прежние
   фото и может их удалять — тогда место освобождается.

   ⚠️ Нюанс: если сайт выложен в интернет, а все гости сидят на одном Wi-Fi,
   наружу они выходят с одним общим IP — лимит станет общим на всех. При
   сервере в локальной сети такой проблемы нет (у каждого телефона свой IP).
3. Фото попадают в статус «На модерации» и в альбоме **не видны**.
4. Админ на `/admin.html` публикует фото (по одному или «Опубликовать все
   новые»), может снять с публикации и удалить **любое** фото.
5. Опубликованные фото появляются на странице «Альбом» (обновляется сама).

## Важно для реального праздника

Камера в браузере (`getUserMedia`) работает только по **HTTPS** (или на
localhost). Если гости заходят по QR через локальную сеть или обычный http,
страница автоматически предложит кнопку «📷 Открыть камеру» — она открывает
нативную камеру телефона (качество даже лучше). Для полного live-режима
выложите сайт за HTTPS (например, `cloudflared tunnel`, ngrok или любой хостинг
с Node.js).

Файлы фото хранятся в `uploads/`, метаданные — в `data/photos.json`.
